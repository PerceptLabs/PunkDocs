# Punk Mods

**Version:** 2.0  
**Status:** Canonical Source of Truth

---

## Overview

A Mod is a self-contained capability package that extends Punk and Mohawk. Mods are developer-built artifacts distributed via Depot.

---

## Key Principles

| Principle | Description |
|-----------|-------------|
| **Developer-built** | Mods are authored by developers, not generated by AI |
| **Self-contained** | Everything needed is in the SQLar archive |
| **Portable** | Works across Mohawk SaaS, Docker, and Desktop |
| **Sandboxed** | Runs in Trinity with capability-based permissions |
| **AI-queryable** | Knowledge docs teach Ska how to use capabilities |

---

## Mod Structure

```
example-mod.sqlar
├── manifest.json           # Mod metadata
├── schema.sql              # Database tables (if needed)
├── lua/                    # Lua code
│   └── main.lua
├── js/                     # JavaScript code
│   └── index.js
├── wasm/                   # WebAssembly modules
│   └── processor.wasm
├── knowledge/              # Docs for Ska to read
│   ├── usage.md
│   └── examples/
│       └── basic.json
├── templates/              # Pre-written code templates
│   └── query.hbs
└── schemas/                # Validation schemas
    └── params.json
```

## SQLar Format

Mods use SQLite Archive format—a SQLite database with embedded files:

```sql
CREATE TABLE sqlar (
  name TEXT PRIMARY KEY,  -- File path
  mode INT,               -- Unix permissions
  mtime INT,              -- Modification time
  sz INT,                 -- Uncompressed size
  data BLOB               -- File contents
);
```

**Benefits:**
- Single file distribution
- Queryable contents
- Atomic operations
- Standard SQLite tooling

## Trinity Runtime

Mods execute in Trinity, a polyglot runtime environment:

| Runtime | Role | Use Case |
|---------|------|----------|
| **Lua** | Scripting & orchestration | Configuration, glue code, simple transformations |
| **Txiki.js** | I/O & networking | HTTP requests, file operations, external APIs |
| **WAMR** | WebAssembly performance | Image processing, encryption, heavy computation |

**Sandboxing:** Mods execute isolated from the core renderer. A malicious mod cannot corrupt Puck or bypass @effect/schema validation.

## Manifest Schema

```json
{
  "name": "example-mod",
  "version": "1.0.0",
  "description": "What this mod does",
  "author": "developer-name",
  
  "capabilities": {
    "requires": [
      "ska:generate",
      "storage:read"
    ],
    "provides": [
      "example:process",
      "example:export"
    ]
  },
  
  "config": {
    "apiKey": {
      "type": "string",
      "secret": true,
      "required": true
    }
  },
  
  "entry": "js/index.js"
}
```

## How Ska Uses Mods

```
┌─────────────────────────────────────────────────────────────────┐
│                    AI INTERACTION PATTERN                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. USER: "Generate an invoice PDF"                             │
│                                                                 │
│  2. SKA:                                                        │
│     ├── Reads knowledge/usage.md from pdf mod                   │
│     ├── Learns: "call pdf:generate with template + data"        │
│     ├── Reads knowledge/examples/invoice.json                   │
│     └── Calls: pdf:generate({                                   │
│           template: 'invoice',                                  │
│           data: { invoiceNumber: 'INV-001', ... }               │
│         })                                                      │
│                                                                 │
│  3. MOD (internally):                                           │
│     ├── Validates params against schema                         │
│     ├── Runs pre-written code (developer-authored)              │
│     └── Returns PDF bytes                                       │
│                                                                 │
│  AI passes DATA to mod. Mod has CODE.                           │
│  AI never generates code. AI never sees mod internals.          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## Agent Mod

A specific mod that transforms Mohawk from v0/Lovable-style into Claude Code-style multi-agent workflows.

**Capabilities:**
- Deterministic multi-step workflow execution
- Agent and sub-agent orchestration
- Cross-run learning and memory
- Full audit trail of every step

**Use case:** Complex application generation requiring architectural planning, design, and implementation phases with multiple specialized agents.

## Knowledge Docs

Knowledge docs teach Ska how to use the mod:

```markdown
---
tags: [pdf, export, document]
---

# Generating PDFs

To generate a PDF, call `pdf:generate` with:
- `template`: Template name ('invoice', 'report', 'receipt')
- `data`: Object with template variables

## Example

pdf:generate({
  template: 'invoice',
  data: {
    invoiceNumber: 'INV-001',
    customer: 'Acme Corp',
    items: [...]
  }
})
```

**Best practices:**
- One topic per file for better retrieval
- Include working, tested examples
- Use frontmatter tags for search
- Keep updated with SDK changes

## Distribution

Mods are distributed via **Depot** (the Punk marketplace):

- Users install mods into their projects
- Mods come pre-built and tested
- Mod authoring done via CLI or Mohawk Desktop
- Mods can be free or tier-gated
